3 分鐘快速體驗

不需要準備任何檔案。工具內建一份虛構學校的範例課程計畫，裡面刻意留了三個常見寫法錯誤，可以直接看到 AI 如何指出「待修正」。

  1. 1載入範例到工具首頁，按「⚡ 3 分鐘快速體驗」或上傳區下方的「📄 載入範例課程計畫」。
  2. 2自動選好項次系統會自動選好「5-1-1 普通班各年級各領域/科目課程計畫」，並顯示審查標準。
  3. 3送出審查有 Gemini 金鑰就按「送出 AI 審查」；沒有金鑰可按「複製提示詞」，貼到 Gemini 或 ChatGPT 網頁版。
開啟工具開始體驗 →

範例刻意留下的錯誤：①領域標示寫成「【國語文】」（應為「語文領域-國語文」且不加【】）②融入議題寫成「【環境教育】、【家庭教育】」（不應加【】）③第 5 週缺少評量方式。

系統架構

整個工具是一個網頁檔案，放在 GitHub Pages 上，不需要安裝、沒有資料庫、沒有我們自己的伺服器保存使用者資料。就像一本放在公共書架上的「審查手冊＋計算機」：每位老師打開後，都在自己的電腦上運算。

元件做什麼在哪裡執行
網頁本體 index.html操作介面、40 多個審查項次與審查標準（內嵌）、結果卡片、匯出功能使用者的瀏覽器
PDF.js（CDN 載入）把 PDF 轉成純文字使用者的瀏覽器
Google Gemini API（或 OpenAI）依審查標準比對文字，回覆「表件通過」或列出待修正處Google／OpenAI 雲端（使用者自己的金鑰）
瀏覽器本機儲存保存金鑰、設定、最近一次審查結果、批次進度使用者的瀏覽器（localStorage／sessionStorage）
Service Worker ＋ manifestPWA：可安裝到桌面、離線開啟介面、新版本提示使用者的瀏覽器
使用狀況通知（可關閉）審查開始／成功／失敗時通知開發者，以便即時排錯Firebase Cloud Functions → Google Chat／LINE

可選模型：Gemini gemini-2.5-flash（預設）、gemini-2.5-pro、gemini-2.0-flash；OpenAI gpt-4o-mini、gpt-4o、gpt-4.1-mini。遇到忙碌或額度錯誤（429／503 等）會自動等待後重試，最多 3 次。

資料流圖

實線是審查必經的路線；虛線是可關閉的使用狀況通知。PDF 原檔從頭到尾都不會離開使用者的電腦，送出去的只有擷取後的文字。

資安與隱私

資料存在哪裡會送到哪裡使用者可以怎麼控制
PDF 原檔只在瀏覽器記憶體不外傳—
PDF 擷取文字瀏覽器記憶體使用者選擇的 AI 服務（Gemini／OpenAI）上傳前刪去學生個資；或改用「複製提示詞」自行貼到網頁版
API 金鑰瀏覽器 localStorage只送到對應的 AI 服務做驗證清除瀏覽器資料即可刪除；建議在 Google AI Studio 為金鑰設定用量上限
審查結果瀏覽器 localStorage（最近一次）不外傳由使用者自行匯出、分享
使用狀況通知—開發者的 Google Chat／LINE（經 Firebase Cloud Functions）API 設定 →取消勾選「傳送使用狀況通知」即停止；或把檔名改成一般名稱再上傳
請勿上傳含學生個資的文件。課程計畫原則上不需要學生姓名、座號或照片；若附件含有，請先刪除再審查。

使用狀況通知的細節

  • 為什麼要有：全市老師在不同時間使用，出錯時開發者能立刻知道哪個項次、哪種模型失敗，盡快修正。
  • 傳送內容：審查項次、PDF 檔名（產生模式為學校、年級、領域、議題）、模型、結果或錯誤訊息、瀏覽器、作業系統、螢幕大小、工具版本，以及連線 IP（由伺服器端讀取）。
  • 不傳送：PDF 內容、AI 回覆全文、API 金鑰。
  • 預設：開啟。v4.3.0 起可在「API 設定」取消勾選，設定記在該瀏覽器，關閉後不再傳送。
  • 通知服務的祕密設定：Google Chat Webhook 網址存在 Google Cloud Secret Manager，不寫在原始碼裡。

AI 與人的分工

AI 像一位「很會對照規定的助教」，能快速把 40 多項標準逐條比對；但通過與否最後由人決定。正式審查結果以教育局審查委員審定為準。

步驟AI 做什麼人做什麼誰做最後決定
1. 撰寫計畫（產生模式）依規則產出草稿教師依學校實際狀況修改、補充撰寫教師
2. 選擇項次與標準—承辦人選項次；門數等條件與規定不同時，直接修改審查提示詞承辦人
3. 比對審查逐條比對，列出待修正處與依據；全部符合則回覆「表件通過」——（僅建議）
4. 複核結果（可選）對待修正項目產生修正稿建議逐項閱讀依據，判斷 AI 是否誤判；確認無誤可按「✅ 人工確認通過」承辦人
5. 修正與重審重新比對修正後的 PDF撰寫教師修正；承辦人重審待修正項承辦人
6. 正式送審—學校依程序送教育局教育局審查委員

一定要人工審查的情況

  • 特殊教育班、藝術才能班、體育班（5-1-2～5-1-4 等）：目前沒有完整專屬標準，選到時畫面會跳出提醒。
  • AI 回覆與標準明顯矛盾、或「依據」引用了文件中不存在的內容。
  • 同一項次重審兩次結果不一致（AI 回答有隨機性）。

已知限制

  • 只支援文字型 PDF。掃描成圖片的 PDF 擷取不到文字（擷取少於 50 字時會提示）。
  • 表格可能跑版。PDF.js 依位置讀字，複雜表格的欄位順序可能被打亂，AI 偶爾會因此誤判「缺少某欄」。
  • AI 可能誤判或漏判。同一份文件重審，結果可能略有不同，請以人工複核為準。
  • 標準只適用 115 學年度。審查標準依桃園市教育局 115 學年度文件內嵌；學年度更新後需要同步修改。
  • 文件太長可能不完整。超過 5 萬字會提示，建議只上傳相關章節或改用 gemini-2.5-pro。
  • 需要 AI 金鑰。沒有金鑰時只能用「複製提示詞」到網頁版；免費額度用完會出現 429 錯誤。
  • 模型會更新或停用。Google 與 OpenAI 會陸續汰換舊模型；若某模型出現「找不到模型」，請改選其他模型。
  • 尚未完成量化驗證。目前沒有「AI 判定與人工審查一致率」與「節省時間」的正式量測數據，規劃中。

常見問題

上傳後顯示「文字過少，可能為掃描圖檔」怎麼辦？
代表 PDF 是圖片。請回到 Word／Google 文件原檔，用「另存為 PDF」或「下載 PDF」重新產生文字型 PDF，不要用掃描或拍照。
出現 429、quota、額度用完？
免費額度在短時間內用完。工具會自動等待重試最多 3 次；仍失敗時請等幾分鐘、改用 gemini-2.5-flash，或隔天再試。批次審查一次跑很多項，最容易遇到。
金鑰錯誤或測試失敗？
到「API 設定」按「🔍 測試 API 金鑰」。確認複製時沒有多空白、金鑰屬於 Google AI Studio（不是 Google Cloud 其他服務），必要時重新建立一把。
沒有金鑰也能用嗎？
可以。選好項次後按「複製提示詞」，貼到 Gemini 或 ChatGPT 網頁版，並把擷取的文字一起貼上。
同一份文件，兩次結果不一樣？
AI 回答有隨機性。請以「依據」欄位對照原文判斷，必要時以人工確認為準。
我們學校的門數規定跟標準不一樣？
選好項次後，直接修改「審查提示詞」裡的條件（例如 3 門改 2 門），再送出審查。
怎麼關閉使用狀況通知？
展開「API 設定」，取消勾選「傳送使用狀況通知給開發者」。設定記在目前的瀏覽器，換電腦需要再設定一次。
可以離線使用嗎？
介面可以安裝成 App 離線開啟，但 AI 審查需要連網呼叫 Gemini／OpenAI。
審查結果會不會被別人看到？
不會。結果只存在您的瀏覽器，除非您自己匯出或分享。

自行部署與改造

A. 直接使用（最簡單）

打開 https://cagoooo.github.io/curriculum/ 即可，不需要安裝。

B. 架一份自己學校的版本

  1. 在 GitHub 按 Fork 複製 cagoooo/curriculum 到自己的帳號。
  2. 到該 repo 的 Settings → Pages，Source 選 main 分支、根目錄，儲存後約 1～2 分鐘即可用 https://<帳號>.github.io/curriculum/ 開啟。
  3. 若 repo 名稱不是 curriculum，請把 sw.js 與 manifest.json 裡的 /curriculum/ 路徑改成新的名稱。
  4. 停用或改接使用狀況通知：在 index.html 搜尋 NOTIFY_URL，把兩個網址換成自己的 Cloud Functions；若不需要通知，在 notifyAdmin() 函式第一行加上 return;。

C. 本機預覽

git clone https://github.com/cagoooo/curriculum.git
cd curriculum
python -m http.server 8000
# 瀏覽器開啟 http://localhost:8000

D. 部署自己的通知服務（選用）

_gchat-fn/ 是 Google Chat 通知的 Cloud Functions 原始碼（Node.js 24）。需要自己的 Firebase 專案：

cd _gchat-fn
npm install
firebase functions:secrets:set GCHAT_WEBHOOK   # 貼上自己的 Google Chat Webhook
firebase deploy --only functions

E. 修改審查標準

審查項次與標準都在 index.html 的 REVIEW_DATA 陣列，每個項次有 id、name、prompt。白話說明在 ITEM_DESC。學年度標準更新時，改這兩處即可。
